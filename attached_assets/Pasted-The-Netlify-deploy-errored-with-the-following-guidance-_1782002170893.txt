The Netlify deploy errored, with the following guidance provided:

Diagnosis
- Relevant log lines: build started with npm run build [#L78-L80], the build script fails because the command/program rsbuild is not found [#L81]. The build command therefore exits with code 127 and Netlify reports the failure [#L83-L91].
- There is also a Node engine warning earlier about @semantic-release/npm requiring a newer Node version than the environment provides [#L19-L22]. (This is a warning, not the immediate cause of the failure, but may need attention.)

Cause
- The package.json build script calls a CLI named rsbuild ("rsbuild build"), but that executable is not present on the build machine, so the shell cannot find it and exits with code 127 [#L81]. This happens when either:
  - the npm package that provides the rsbuild binary is not listed in package.json or not installed, or
  - rsbuild is a local script/binary that wasn't committed to the repo, or
  - the build script is wrong and names a tool that you don't intend to use.

Solution
1) Inspect your repository's package.json to confirm what your "build" script is and whether rsbuild is listed as a dependency/devDependency:
   - Open package.json in the repo: https://github.com/M0had1/trading-bot-template/blob/master/package.json
   - Look for the "scripts.build" entry and for "rsbuild" under dependencies/devDependencies.

2) If you intend to use the rsbuild npm package:
   - Verify rsbuild is in package.json. If it is missing, add it (as a devDependency) and commit package.json and package-lock.json:
```bash
npm install --save-dev rsbuild
git add package.json package-lock.json
git commit -m "Add rsbuild as devDependency"
git push
```
   - Redeploy on Netlify. Installing rsbuild ensures the binary will be available at node_modules/.bin/rsbuild and npm run build will find it.

3) If rsbuild is a local script/binary (e.g., a file in the repo that provides rsbuild):
   - Verify that file was committed. If not, add & commit it and push. Netlify needs the file present in the repo to execute it.

4) If rsbuild is a typo or you intended to use another builder (vite, react-scripts, webpack, etc.):
   - Update package.json to call the correct build command. Example change (replace with the correct tool you use):
```json
"scripts": {
  "build": "vite build"
}
```
   - Commit and push the change.

5) Re-deploy. The immediate error should be resolved once the build script references an installed/committed executable.

6) (Optional) Address the Node engine warning: @semantic-release/npm declared an engine requiring newer Node [#L19-L22]. If you need that package to run in CI, set the Node version Netlify uses (e.g., via .nvmrc or environment settings). Netlify docs for changing Node versions: https://docs.netlify.com/configure-builds/manage-dependencies/#node-js-and-javascript

Notes
- Do not rely on globally installed CLIs on your local machine; always add build tools as local dependencies or include committed scripts so they are available in Netlify's build environment.
- After making the change, check the build logs for the successful invocation of the expected binary (e.g., node_modules/.bin/rsbuild or vite) rather than the "not found" error shown at [#L81].
