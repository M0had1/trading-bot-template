The Netlify deploy errored, with the following guidance provided:

Diagnosis

- The build command in Netlify is "npm ci && npm run build" ([line 9](#L9), [line 115](#L115)). The npm "build" script runs "rsbuild build" ([line 103](#L103)) and fails because the rsbuild executable is not available: "sh: 1: rsbuild: not found" ([line 105](#L105)). This produces exit code 127 and causes the deploy to fail ([line 111](#L111)–[line 116](#L116)).
- There is also an npm engine warning about @semantic-release requiring a newer Node than the build environment provides ([line 19](#L19)–[line 22](#L22)). That is a warning and not the primary failure, but if you need to match Node versions you can change Netlify’s Node version (see link below).

Cause
- The script "rsbuild build" refers to a program named rsbuild that is not installed or not present in the repo. Netlify runs npm ci (which installs dependencies from package.json) and then runs the build script; if rsbuild is not present as a dependency/bin or as a committed local file, the command will fail with "not found".

Actionable solution

1) Inspect your package.json build script and confirm what "rsbuild" should be
- Open package.json and check the "scripts.build" entry:
  https://github.com/M0had1/trading-bot-template/blob/master/package.json

2) If rsbuild is provided by an npm package
- First verify the package is listed in package.json under dependencies or devDependencies. If it is missing, add it and commit:
  - Example (run locally and commit the updated package.json and package-lock.json):
  ```bash
  npm install --save-dev rsbuild
  git add package.json package-lock.json
  git commit -m "chore: add rsbuild devDependency"
  git push
  ```
  - Re-deploy on Netlify. This makes the rsbuild binary available to npm scripts (npm puts package bin entries on PATH when running scripts).

- Alternatively, if you prefer not to add it permanently, you can change the build script to use npx so Netlify will fetch the binary at runtime:
  - In package.json change:
    "build": "rsbuild build"
    to
    "build": "npx rsbuild build"
  - Commit and re-deploy.

3) If rsbuild is a local script/binary in your repo
- Verify the file was committed (for example scripts/rsbuild or bin/rsbuild). If it’s missing, add & commit it. Make sure it is executable (unix +x) if necessary.
- If it exists but was not referenced correctly, update package.json to call the correct path:
  - Example:
  ```json
  "build": "node ./scripts/rsbuild build"
  ```
  or
  ```json
  "build": "bash ./scripts/rsbuild build"
  ```

4) If you did not intend to use rsbuild
- Update the build script to call the correct build tool for your project (for example "vite build" or "react-scripts build" or whatever produces the dist/ output). Commit and re-deploy.

5) Reproduce locally and test
- Run locally to verify the same commands succeed:
  ```bash
  npm ci
  npm run build
  ```
  Fix any errors locally, commit, and push.

6) Node engine warning (optional)
- The logs include an EBADENGINE warning for @semantic-release requiring a newer Node ([line 19](#L19)–[line 22](#L22)). If you need to change the Node version used by Netlify, follow Netlify docs:
  https://docs.netlify.com/configure-builds/manage-dependencies/#node-js-and-javascript
