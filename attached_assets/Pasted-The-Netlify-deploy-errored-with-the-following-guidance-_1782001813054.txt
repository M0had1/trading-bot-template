The Netlify deploy errored, with the following guidance provided:

Diagnosis
- Relevant log lines:
  - [line 78](#L78)-[line 81](#L81) show the build command being run and the failure: the npm "build" script runs "rsbuild build" and the shell reports "rsbuild: not found" ([line 81](#L81)).
  - The build then exits with non-zero status ([line 82](#L82), [line 88](#L88)).
  - There is an earlier npm internal warning/error ("Exit handler never called!") at [line 38](#L38)-[line 41](#L41) — this appears during install but the log says "npm packages installed" afterwards, so the fatal failure is the missing rsbuild binary.
  - There is also an engine warning about Node version mismatch at [line 19](#L19)-[line 22](#L22); it’s a warning, not the build failure, but you may want to align Node versions.

Root cause
- The build script in package.json runs the command rsbuild, but Netlify’s build environment does not have an rsbuild binary available (it wasn’t installed or committed). That causes the shell error "rsbuild: not found" and the build to fail.

Solution
1. Verify whether rsbuild should be provided by a package or is a committed/local file
   - Open your package.json to confirm the "build" script and whether rsbuild is declared as a dependency/devDependency:
     - package.json: https://github.com/M0had1/trading-bot-template/blob/master/package.json
   - If rsbuild is a local script/binary (for example a file under your repo like bin/rsbuild), verify that file was committed to the repo.

2. If rsbuild is a Node package (most likely), add it to package.json and commit
   - In your project root run locally:
     - npm install --save-dev rsbuild
     - or if the maintainer package name is different, install the correct package (check your repo docs/README).
   - Test locally: npm run build (ensure it runs successfully).
   - Commit package.json and package-lock.json and push to your repo so Netlify will install it during the build.

3. If rsbuild is a local executable script
   - Ensure the file is in the repo and executable. Example:
```bash
# if the script is at bin/rsbuild
git add bin/rsbuild
git commit -m "Add rsbuild script"
git push
```
   - Confirm package.json references it correctly (scripts use node_modules/.bin or ./bin path).

4. Re-run the Netlify build
   - After pushing the change (installed package or committed script), Netlify will re-install deps and the rsbuild executable should be available, so the build should proceed.

Optional: address the Node engine warning
- The logs show an engine warning for @semantic-release/npm requiring newer Node ([line 19](#L19)-[line 22](#L22)). If you need to match a required Node version, set Node on Netlify; see Netlify docs for changing Node versions:
  - https://docs.netlify.com/configure-builds/manage-dependencies/#node-js-and-javascript

Notes about the npm internal error
- The "Exit handler never called!" message at [line 38](#L38) is an npm internal error/warning. If you see install failures or odd npm behavior after addressing rsbuild, try switching Node versions or clearing caches and re-running installs locally to reproduce. If it persists and blocks installs, consider trying a different npm/node version or using yarn; refer to the Node version docs linked above.
